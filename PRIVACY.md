# Privacy

Enigma Volunteer Grid is designed to collect the minimum information needed to coordinate volunteer computation, validate results, and assign optional public credit.

## What the coordinator receives
- A contributor display name chosen by the volunteer.
- Random contributor and device identifiers generated by the system.
- Sanitized hardware capabilities needed for scheduling, such as CPU thread count, GPU model/memory, and whether the OpenCL GPU self-test passed.
- Resource preferences such as CPU/GPU contribution percentages.
- Contribution records: work ranges, validation state, verified units/jobs, compute time, candidate counts, trust score, and timestamps.
- A last-seen timestamp so the dashboard can distinguish online and offline devices.

The worker does not upload personal files, browser data, passwords, email addresses, Windows account names, local file paths, GPU UUIDs, hostnames, or arbitrary process information.

## Credentials and network data
Device, contributor, and dashboard credentials are random secrets. The server stores hashes rather than the original secrets. On Windows, the local client state is encrypted with DPAPI for the current Windows user.

The public service may see a source network address transiently as part of normal networking and rate limiting. The application does not write source IP addresses into contributor/device records or contribution tables. Rate-limit keys are hashed in memory.

## Public information
A contributor appears on the public leaderboard only when public credit is enabled. Public leaderboard data is limited to the chosen display name and aggregate contribution statistics.

## Deletion
A contributor can request account deletion using the private dashboard credential. Deletion removes the contributor record, devices, submissions, contribution/credit rows, and device audit rows. Completed search ranges remain part of the scientific campaign but their device reference is changed to "deleted".

Uninstalling the Windows app removes the application. Local contributor identity/settings are retained by default so a later reinstall can resume the same identity; the uninstall UI offers an explicit option to delete them too.

## Updates and telemetry
The application checks signed project releases for updates. There is no advertising SDK, analytics SDK, or behavioral tracking in the client.

## Security boundary
The coordinator sends structured work descriptions for solver engines already included in the worker. It does not send shell commands or arbitrary executable code for volunteers to run. The update manifest is signed; Windows executables do not currently carry an Authenticode publisher signature.

Security issues should be reported privately according to SECURITY.md rather than opened as a public issue when disclosure could put volunteers or the coordinator at risk.
